# 🎓 E-Campus – Flutter College Management App

## 1. Project Description

**E-Campus** is a mobile-based college management application developed using Flutter and Dart. The application aims to simplify communication and information sharing between students, teachers, and college representatives through a single digital platform.

The app provides features such as user authentication, role-based dashboards, an electronic library, student–teacher communication, college bus tracking, notifications, and an AI-powered chatbot.

The application is designed to make college-related information easily accessible, reduce manual communication, and improve the overall campus experience. Its modular design allows different users to access features according to their roles.

### Objectives

* Develop a user-friendly mobile application for college management.
* Provide secure login and registration for users.
* Display role-specific features for students, teachers, and class representatives or administrators.
* Provide access to digital learning resources.
* Improve communication between students and teachers.
* Help students view college bus locations through map integration.
* Provide an AI chatbot for answering student queries.
* Deliver timely notifications and reminders for important academic activities.

## 2. Features

### 2.1 User Authentication

* User registration and login.
* Firebase Authentication integration.
* OTP-based verification, where configured.
* Authentication-based access to application screens.

### 2.2 Role-Based Access Control (RBAC)

* Separate menus and dashboards according to user roles.
* Student-specific academic and communication features.
* Teacher and class representative/admin options, according to assigned permissions.

### 2.3 E-Library

* Access to digital books and learning resources.
* Browse educational materials.
* Provide students with a centralized place for study resources.

### 2.4 Chat and Communication

* Communication between students and teachers.
* Chat with friends, where enabled.
* A centralized interface for college-related discussions.

### 2.5 College Bus Tracking

* Google Maps integration for displaying bus locations.
* A map-based interface for campus transportation.
* Location updates and live tracking when a suitable location service and backend are configured.

### 2.6 AI Chatbot

* Integration with the ChatGPT API.
* An interface for asking academic and college-related questions.
* AI-generated responses to help students find information.

### 2.7 Notifications and Reminders

* Notifications for assignments, classes, and campus reminders.
* Configurable reminder times.
* Android notification permissions and scheduling.

## 4. Application Workflow

The general application workflow is:

1. The user opens the E-Campus application.
2. The app displays the login or registration screen.
3. The user enters the required credentials and completes verification if enabled.
4. Firebase Authentication validates the user's identity.
5. The application retrieves or determines the user's assigned role.
6. The appropriate dashboard and navigation menu are displayed.
7. The user selects a feature such as E-Library, Chat, Bus Tracking, or AI Chatbot.
8. The application accesses the relevant local or cloud service.
9. The requested information or response is displayed.
10. The user can navigate to other available features or log out.

## 8. Configure Firebase

If Firebase is used by the current project, follow these steps:

1. Open the Firebase Console: https://console.firebase.google.com/
2. Create a Firebase project or open the existing project.
3. Register an Android application using the exact Android application ID from the project's Gradle configuration.
4. Download the appropriate `google-services.json` file.
5. Place it in the Android app module's expected location, commonly `android/app/google-services.json`.
6. Configure the Google Services Gradle plugin and Firebase dependencies as required by the project's current setup.
7. Enable the authentication providers required by the application.
8. Configure OTP verification and any associated provider settings if phone authentication is implemented.
9. Configure any additional Firebase services used by the application.

**Note:** Do not replace existing Firebase configuration files blindly. If the project already has a working Firebase setup, preserve it.

Official documentation: https://firebase.google.com/docs/flutter/setup

## 9. Configure Google Maps

If the bus tracking feature uses Google Maps:

1. Open the Google Cloud Console: https://console.cloud.google.com/
2. Create or select a project.
3. Enable the required Maps SDK for Android.
4. Configure API credentials and restrictions.
5. Add the API key using the configuration method expected by the project.
6. Ensure that the Android application has the required location permissions if it accesses the device's location.
7. Test the map on a physical device with internet and location services enabled.

A map displaying successfully does not automatically mean live bus tracking is working. Live tracking also needs a source of bus location updates, such as a backend or location-sharing service.

## 10. Configure the AI Chatbot

If the application calls the ChatGPT API:

1. Obtain API access from https://platform.openai.com/
2. Configure the required API credentials and endpoint.
3. Connect the chatbot interface to the request and response logic.
4. Handle loading states, network errors, and API failures.
5. Test with a simple question and verify that a response appears.

**Security:** Never commit a real API key to a public GitHub repository or embed a secret key directly in a distributed mobile application. Use a backend service to protect the key, and keep credentials in secure configuration or secret-management systems.

## 15. Troubleshooting

### Flutter does not detect the phone

* Enable USB debugging.
* Unlock the phone and authorize the computer.
* Try a different USB data cable or port.
* Run `flutter devices` again.

### Dependency installation fails

Run:

```powershell
flutter pub get
```

Check the error message and internet connection. Avoid upgrading every dependency indiscriminately, as that can introduce compatibility problems.

### Android build fails

Run:

```powershell
flutter doctor
flutter analyze
```

Review the first actual build error and verify that the installed Android SDK and project Gradle configuration are compatible.

### Google Fonts fails to load

If the project depends on downloading Google Fonts at runtime, an emulator or phone without internet access may not load those fonts. Use bundled font assets or an appropriate offline-safe font configuration.

### Firebase login fails

Verify the Firebase configuration, authentication provider settings, internet connectivity, and the package ID registered with Firebase.

### Google Maps is blank

Check the API key, API enablement, application restrictions, billing requirements, internet access, and location permissions.

### Notifications do not appear

Check notification permission settings, Android notification-channel settings, scheduled notification logic, and device battery restrictions.

### AI chatbot does not respond

Check the network request, backend availability, API credentials, response parsing, and API usage limits. Never expose private credentials in logs or a public repository.
